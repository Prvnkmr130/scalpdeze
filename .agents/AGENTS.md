# Project Rules & Guidelines

## 1. Strategy Engine Standards
- **Production Engines**: Use the unified master engines `indian_opt_trde_polars.py` and `crypto_opt_trde_polars.py` as active production engines. Legacy standalone broker-specific strategies (`zerodha_opt_trde_polars.py`, `kotak_opt_trde_polars.py`, `coinswitch_opt_trde_polars.py`, `delta_opt_trde_polars.py`, `zerodha_opt_trde_optimized.py`) have been permanently removed from the repository. The reference baseline `zerodha_opt_trde_reference.py` is preserved strictly for offline baseline comparison.
- **Early Ingestion Filtering (`build_aug_table`)**: Filter candidate instruments at the earliest configuration ingestion boundary via `build_aug_table(stock_data_info)` in `polars_excel.py`, strictly requiring `Capital_share > 0` and `Max_lots_per_order > 0`. Explicitly ignore `Tradable_stock` (pending future deprecation/removal). Never load contracts, fetch ticks, or run calculations on zero-capital underlyings.
- **Static Algorithm Registry**: Maintain the static list of active algorithms in `algo_trading/algos/__init__.py`. Load modules inside `load_all_algos()` to avoid circular imports.
- **In-Memory Debounce Counters**: Always use native Python dictionaries (`Dict[int, int]`) for debounce and state counters (`one_counter_ce_dict`, `hedge_counter_dict`, etc.) for $O(1)$ fast lookups instead of allocating DataFrames.
- **Dynamic Dtype Safety**: Support fractional strike prices and LTPs (`Float64` / `Int64`) safely without hardcoded `int()` truncations.
- **Numeric Dtype Casting at Config Ingestion**: Explicitly cast `cap_config` columns (`tradable`, `minimum_lots_to_buy`, `maximum_lots_to_buy`, `preference` → `Int64`; `lower_price_limit`, `upper_price_limit` → `Float64`) at load time in `polars_excel.py` and after `cap_config` joins in `indian_master_tokens.py` / `crypto_master_tokens.py`. Cast `tradable` to `int` via safe parsing (`int(float(str(val).strip()))`) with fallback to `0` before evaluating buy-gate conditions in execution loops. Never compare raw `openpyxl`-sourced values directly against integer literals.
- **`algo_dir` Fallback Input File Resolution**: Resolve `input_file` paths (`token_ref.xlsx`, `token_ref_bitcoin.xlsx`) by first checking `data_file_path` (project root), then falling back to `algo_dir` (`os.path.dirname(os.path.abspath(__file__))`) where Excel config files actually reside. This ensures correct file discovery inside Docker containers where `data_file_path` is `/app/` but files live at `/app/algo_trading/algos/`.
- **`AlgoInfo` Database Sync & Token Subscription Parity**: Production strategy engines (`crypto_opt_trde_polars.py`, `indian_opt_trde_polars.py`) must maintain complete state persistence parity in the `kalai_algoinfo` database table. Specifically: (1) persist subscribed tokens to `{account_id}_inst_tokens` via `broker.set_subscribed_tokens(sym_list)` so streaming feeds dynamically subscribe to genuine contracts, (2) persist resampled multi-timeframe candles (`fwd_10_all`, `fwd_30_all`, `fwd_60_all`, `day_cdl_all`) via `broker.set_algo_state()` using in-memory deduplication caching (`_candle_cache`) to avoid redundant writes, and (3) persist parsed Excel configuration tables (`stock_config`, `stock_data_info`, `cap_config`) via `update_config_info()`. Target brokers for persistence (`_get_target_brokers()`) must strictly filter for active accounts where `enable_trade=True`. Accounts with `enable_trade=False` must never receive candle arrays, token table subscriptions, or config snapshots in `kalai_algoinfo`.
- **Separation of Master Universe vs. Dynamic Subscription (`token_list_update`)**: Master contract assembly (`load_master_token_list()`) resolves the full static candidate universe (`cum_table` & `inst_list_int`, 900+ rows). Never subscribe `cum_table` tradingsymbols or `inst_list_int` directly to live data feeds (`inst_list_int` in reference engines was solely for matrix counter sizing). Live feeds must strictly subscribe the minimal active set resolved by `token_list_update()`: underlying reference symbols (`init_ref_list`), index tokens, active positions/holdings, and dynamically selected ATM/OTM strikes (`Buy_strike == 'Yes'`) (~8 to 15 tokens total).
- **Strike Detection Expiry, Buffer & Offset Integrity**: In `strike_detect()` / `detect_strike_side()`, always add `Strike_dist_CE` and `Strike_dist_PE` offsets to candle averages ($\text{est\_strike} = \text{candle\_avg} + \text{Strike\_dist}$), filter candidate options by `exp_date_list > month_cutoff`, and enforce `cap == cap_info` (supporting both `weekly_options` and `weekely_options`). For Indian options (`indian_opt_trde_polars.py`), enforce `expiry > tomorrow` (`expiry > today + 1 day`) and filter by `min_week`. For crypto options (`crypto_opt_trde_polars.py`), enforce a **3-day lower cutoff and 7-day upper cutoff** (`3 <= days_to_expiry <= 7`) selecting the derivative expiring **last in the week** (`max(expiry)` within the nearest eligible week). If no contract exists in the 3-to-7 day range, extend the window to 14 days (`3 <= days_to_expiry <= 14`) and select the contract expiring **early** (`min(expiry)`). When filtering crypto options, accept both weekly and monthly options across the 3 to 14-day window so rollover is not blocked by static `cap` tags. In `crypto_master_tokens.py`, compute `week_dist` as integer calendar week offsets (`((truncate_1w(expiry) - truncate_1w(today)) // 7)`), classify contracts expiring within 15 days as `weekely_options`, and cast `week_dist` to `Int64` upon `cum_table` restoration in `delta_utils.py` and `coinswitch_utils.py`. `execute_trade_cycle()` must dynamically invoke `token_list_update()` and `insert_instrument_token()` in each execution cycle to keep WebSocket feeds synchronized with active strikes.
- **Canonical Tick Token Normalization (`normalize_ticks`) & Dual-Key Resilient Strike Detection**: Incoming market ticks from broker WebSocket feeds / `ProcessedTickStore` can arrive with string symbols (e.g. `'BTCUSD'`, `'NIFTY 50'`) or hashed tokens. Trading engines (`crypto_opt_trde_polars.py`, `indian_opt_trde_polars.py`, `indian_strike_engine.py`) must normalize ticks via `normalize_ticks()` using `cum_table` mappings (`tradingsymbol` → `instrument_token`) so that tick tokens match genuine contract tokens (`Ref_stock_tkn`). In `strike_detect()`, tick filtering must be dual-key resilient (`(instrument_token == ref_tkn) | (tradingsymbol == ref_stock_name)`), with explicit entry/exit/skip lifecycle logging, and PE put strike selection must accept At-The-Money equality (`ratio <= 1.0`).
- **Tier 1 Market Calculation Precedence**: Shared Tier 1 market calculations (`compute_market_signals()`, `update_all_candles_batch()`, `strike_detect()`, `token_list_update()`, `insert_instrument_token()`) must execute before individual account gating (`if not target_acc or not target_acc.enabled`). This ensures market candles, active strikes, and streaming token subscriptions remain continuously synchronized even if a specific account is unauthenticated, paused, or disabled.
- **Pre-Flight Broker Credential Validation**: Verify `api_key` and `api_secret` completeness upon engine initialization and trading loop entry. If an account has `enable_trade = True` but incomplete credentials, log a single warning and mark `enabled = False` to prevent high-frequency error loops. Implement dynamic re-checking so live trading activates automatically as soon as credentials are updated in the database.
- **Per-Symbol Rate Limiting in `BaseFeed`**: In [`algo_trading/brokers/base.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/brokers/base.py), tick rate limiting must be tracked per instrument/symbol (`_last_tick_times: dict[str, float]`) rather than globally per feed. High-volume instruments (e.g. `BTCUSD`, `NIFTY 50`) must never starve or suppress ticks for secondary underlyings or active option contracts.
- **Non-Truncating Tick Ingestion & 180s Cutoff Removal**: `fetch_recent_ticks()` must not enforce mandatory `seconds=180` time-window queries. When `seconds` is omitted (`seconds=None`), fetch the most recent available ticks per instrument from `ProcessedTickStore` or partitioned stream tables so that off-hours, weekend, or illiquid contracts are not discarded.
- **Hierarchical Price Resolution & ATM Float Rounding in `strike_detect`**: Never abort or skip strike detection for an underlying simply because recent ticks are absent (`if recent_ticks.is_empty(): continue` is forbidden). Instead, calculate `candle_avg` hierarchically: (1) 3-minute candle midpoint (`ref_fwd_3`), (2) latest tick price (`recent_ticks['last_price'][-1]`), (3) contract reference price in master universe (`matching_ref['last_price'][0]`), (4) daily candle close (`day_cdl_all`) or base price fallback (`KNOWN_CRYPTO_BASE_PRICES`). Round distance ratios (`round(6)`) before comparing `ratio >= 1.0` (CE) and `ratio <= 1.0` (PE) to prevent 64-bit floating point inaccuracies from dropping At-The-Money (ATM) strikes.
- **Forward Option Chain Synthesis for Underlyings Lacking Exchange Options**: When assembling crypto contract universes (`assemble_crypto_cum_table()`), detect underlyings in `aug_table` that lack forward options expiring strictly after tomorrow (`expiry > tomorrow`) (e.g., SOL, XRP, and daily-only ETH on Delta Exchange India). Synthesize standardized CE and PE option chains centered around the underlying base price across weekly/monthly expiries to ensure all configured underlyings select 1 CE + 1 PE strike, yielding $(N \text{ underlyings} + 2N \text{ strikes} = 12 \text{ tokens for } N=4)$ in `{account_id}_inst_tokens`.
- **Unified Multi-Broker SIMD & Incremental O(1) Candle Engine (3m Base)**: Both Indian (`indian_opt_trde_polars.py`) and Crypto (`crypto_opt_trde_polars.py`) master engines delegate candle updates exclusively to `algo_trading/algos/indian_candle_engine.py`: (1) In raw market ticks, `last_price` is strictly prioritized over broker-provided summary `open`, `high`, `low`, and `close` fields (which often contain 24-hour daily rolling extremes); any summary OHLC columns in raw ticks must be stripped prior to aggregation; (2) On cold start or startup warmup, multi-token batch downsampling is bootstrapped via `group_by_rolling_window()`; (3) In active 2-second trading loops, incoming ticks are downsampled directly into 3-minute base candles (`fwd_3_all`), eliminating intermediate 1-minute memory buffers and allocations. Only the single active (latest) 3-minute bar per token (`active_3m`, $O(1)$) is extracted and passed to `update_candles_incremental()` to update higher timeframes (`fwd_5_all`, `fwd_10_all`, `fwd_15_all`, `fwd_30_all`, `fwd_60_all`, `day_cdl_all`). Within the active time bucket, the latest candle's `close`, `high`, and `low` are updated in place; when the timeframe delta elapses, a new candle is created where `open` strictly equals the previous candle's `close`. Each token retains at least 25 bars (`MAX_CANDLE_HISTORY_BARS`), eliminating 1,500-bar memory buffers. Historical session context is preserved across date boundaries, and stale/expired contracts are evicted via time-horizon filtering.
- **Continuous Candle Lifecycle, Startup Warmup & EOD Persistence**: On engine initialization, `read_db_candle()` restores historical multi-timeframe candles (`fwd_10_all`, `fwd_30_all`, `fwd_60_all`, `day_cdl_all`, `prev_day_cdl_all`) from `kalai_algoinfo` without discarding records due to calendar date differences, and warms up from `ProcessedTickStore` (via `fetch_recent_ticks(seconds=None, limit=120000)`) if available. On EOD or date rollover, `check_eod_cleanup()` preserves `day_cdl_all` into `prev_day_cdl_all` in DB and clears raw tick buffers, but strictly preserves multi-timeframe candle tables in DB (never resetting them to `[]`) so chart visualizers and strategy warmups have immediate candle data at next market open.
- **Candle Visualizer Timezone Parity & Account Isolation**: The Django Admin Candle Visualizer API (`candle_visualizer_api_view` in `kalai/admin.py`) must interpret naive timestamps for Indian brokers as `Asia/Kolkata` IST (and UTC for crypto brokers) before deriving Unix epoch seconds, preventing Docker UTC offset shifts. Lightweight Charts must render with `timeZone: "Asia/Kolkata"` for precise IST X-axis ticks and crosshair legend timestamps. When a specific `account_id` is queried and has no records, the visualizer must never cross-fall-back to another broker's records.
- **In-Process WebSocket Feed Lifecycle, Zero-Feed Standby & 24/7 Crypto Streaming**: The WebSocket streaming engine (`algo_trading/brokers/engine.py:run_engine`) must manage broker feeds dynamically in-process (`start_account_pipeline`, `stop_account_pipeline`, `_handle_reload`) upon receiving PostgreSQL `engine_control` NOTIFY events. Never terminate the process or invoke `os.kill(..., signal.SIGTERM)` on account start/stop events, ensuring 24/7 crypto feeds remain continuously streaming when equity accounts close. When zero feeds are active at startup or after hours, `run_engine()` must enter a non-blocking standby loop rather than exiting with `return` to prevent Supervisord restart exhaustion (`FATAL` state). A background task (`reconcile_feeds_loop`) must reconcile active pipelines against database states every 30s. In `kalai.tasks.evaluate_websocket_schedules`, all active cryptocurrency accounts (`is_crypto=True` and `enable_trade=True`) are guaranteed 24/7/365 WebSocket execution regardless of market-hour schedule toggles.
- **Reconciler Restarts on Credential Changes Only**: `reconcile_once()` in `engine.py` must compare only `access_token`, `api_key`, and `api_secret` when deciding whether to restart a running feed pipeline. Never include `instrument_tokens` in the comparison — `token_list_update()` updates subscribed tokens every 2 seconds, so a token-set diff at 30-second reconciler intervals causes spurious WebSocket disconnects, re-authentication storms, and tick data gaps (observed with Kotak Neo account W1NPY).
- **Close Django DB Connections in `asyncio.to_thread` Token Refresh Workers**: `BaseFeed._read_tokens_from_db()` executes inside `asyncio.to_thread()`. Always call `django.db.connection.close()` in a `finally` block at the end of the function so the thread-local psycopg connection is returned to the pool. Without teardown, each 5-second refresh spawns a new idle DB connection that is never closed, exhausting the pool across multi-feed deployments and causing `"couldn't get a connection after 10.00 sec"` errors in all feeds and background tasks.
- **Minimum `TOKEN_REFRESH_INTERVAL` of 30 Seconds**: Set `EngineConfig.TOKEN_REFRESH_INTERVAL` to at least `30.0` seconds. At 5-second intervals, a multi-feed deployment generates ≥12 concurrent Django thread-connections per feed per minute, rapidly exhausting the pool even with proper `connection.close()` teardown. Token changes are delivered in real-time by `on_tokens_changed()`; the DB poll is only a safety net.
- **Normalize Broker List-Batch Payloads to Per-Tick Frames**: When a broker WebSocket delivers a list of tick dicts in one message (e.g. Kotak Neo HSM `on_message`), enqueue each dict as a **separate** normalized frame via `normalize_tick(tick_item)`. Never wrap the entire list in a single `make_frame(raw_data)` call — this stores a JSON array as one opaque blob in `{account_id}_stream_kv` and `kalai_processedtickstore`, breaking per-instrument tick filtering, candle engine ingestion, and `fetch_recent_ticks()` queries.
- **Architectural Memory Footprint, Connection Pooling & Token Ingestion Filtering**: To preserve sub-1GB RAM container baselines on cloud servers: (1) Connection pooling in `algo_trading/settings.py` must differentiate management commands (`_is_management_cmd`, `min_size: 0`, `max_size: 2`, `max_idle: 15s`) from web server ASGI (`min_size: 0`, `max_idle: 30s`, no hardcoded `max(..., 10)` ceilings) so idle PostgreSQL client backends cleanly terminate; (2) Master token assemblers across both Indian (`indian_master_tokens.py`) and Crypto (`crypto_master_tokens.py`) engines must filter raw exchange scrips to active `aug_table` underlyings and index roots before calling `token_mapper.register_broker_instruments()` or concatenating derivative tables; (3) Strategy loop engines (`algo_engine.py`) must call `ctypes.CDLL('libc.so.6').malloc_trim(0)` alongside `gc.collect()` every 10 cycles to return unreferenced heap pages to the Linux kernel; (4) Django-Q (`Q_CLUSTER`) must enforce `max_rss: 120000`, `recycle: 50`, and `save_limit: 20` to prevent worker memory sprawl.

## 2. Logging & Account Context Standards
- **ISO Timestamp Formatting**: All log entries generated in algorithms and system components must attach an ISO timestamp (`[{datetime.now().isoformat()}]`) to each log entry upon creation.
- **Static Algorithm Identity & Context Binding**: Define an explicit static module-level `_CURRENT_ALGO_NAME` in every strategy file. Bind active account and algorithm name via `algo_logger.set_active_account(broker, algo_name=_CURRENT_ALGO_NAME)` **strictly after** validating broker compatibility (e.g. verifying broker asset class and account support) to prevent premature thread context pollution.
- **Guaranteed Context Teardown (`try...finally`)**: Always enclose strategy executions and sequential loop account passes in `try...finally: algo_logger.clear_active_account()` to prevent thread-local context leaks across loop cycles.
- **ThreadPool Worker Context Propagation**: When spawning worker threads via `ThreadPoolExecutor` (e.g. in `CryptoUserAccount.sync_account_state` and `IndianUserAccount.sync_account_state`), wrap tasks in a context propagator (`_run_with_account_context`) to bind thread-local account and algorithm context with guaranteed `try...finally: algo_logger.clear_active_account()` cleanup.
- **Account Identifier Log Inference & Engine Alignment**: When logging errors mentioning specific broker accounts without an explicitly passed `Broker` object, `algo_logger.log_sync` extracts candidate account identifiers via regex to resolve the exact `Broker` instance and aligns the algorithm identity based on broker class (crypto vs Indian).
- **System Registry Context Cleansing**: The algorithm registry loader (`load_all_algos()`) must explicitly call `algo_logger.clear_active_account()` at entry so framework-level discovery and skipping logs are never misattributed to previous account threads.
- **No Module-Level Context Mutation**: Never set `_ACTIVE_CONTEXT.algo_name` or `algo_logger.context.algo_name` at module import time; context must only be bound inside strategy execution routines after broker validation.
- **Framework Log Isolation**: `InterceptDBLogHandler` must never attach to `"algo_trading.algos"` or intercept framework registry discovery logs (`load_all_algos()`), and must drop `DEBUG` records to prevent log table pollution. Unassigned framework logs must default to `"SYSTEM"`, never defaulting to any specific trading algorithm.
- **No Unconstrained Fallback Logging**: Never fallback to `Broker.objects.first()` for general or lifecycle logs (`BROKER_API`, `SYSTEM`, `APP`); attribute logs strictly to the active enabled broker or leave account context unassigned (`broker=None`).
- **In-Memory Buffering & Periodic Batch Flushing**: Algorithm and system logs must be buffered in memory and written to the database periodically using batch limits (`LOG_BATCH_SIZE_LIMIT`) or time intervals (`LOG_FLUSH_INTERVAL`) via `flush_if_needed()`.
- **Server Load Optimization**: Avoid immediate forced database writes (`force=True`) during routine logging or parameter update requests to reduce database write queries and keep server overhead low.
- **Conclusive Return Logging & Decision Transparency**: All algorithmic methods in unified strategy engines (`indian_opt_trde_polars.py`, `crypto_opt_trde_polars.py`) must emit an informative log immediately before every `return` statement (including early-exit guards, input validation rejections, and completion summaries). Crucial algorithmic branch decisions must use standardized, traceable prefix tags:
  - `[ORDER_GATE]`: Order rejection reasons (invalid quantity, zero price, missing account).
  - `[ORDER_STATUS]`: Order dispatch results (placed order ID, transaction type, stop-loss registration/cleanup).
  - `[ALGO_GATE]`: Account-level skipping reasons (broker disabled, missing API credentials, unauthenticated, asset class mismatch).
  - `[CYCLE_SUMMARY]`: Engine iteration heartbeat (duration, active vs total accounts, selected strikes, streaming tokens).
  - `[MOM_SIGNAL]`: Momentum technical evaluation telemetry (LTP, high/low range, buy signals, jump signals).
  - `[DERIV_ANALYSIS_COMPLETE]`: Derivative analysis strike selection results (buy candidates, exit candidates across open positions).
  - `[TRADE_LOOP_SUMMARY]`: Account order cycle results (`sells_attempted`, `sells_placed`, `buys_attempted`, `buys_placed`, live balance).
  - `[SLU_SUMMARY]`: Trailing stop loss maintenance results (active stop losses tracked, open positions monitored).
  - `[ORDER_PENDING_SUMMARY]`: Pending order watchdog results (scanned open orders, cancelled stale orders).
  - `[MARKET_SIGNALS]`: Tier 1 market signal calculation results (ingested delta ticks, retained buffer size, evaluated ref tokens, candidate signals).
- **Bounded Log Queries & Values Ingestion (`kalai_algolog` / `system_logs`)**: Diagnostic views, anomaly analyzers (`LogAnomalyAnalyzer`), and export utilities (`process_and_export_algo_logs`, `export_algo_logs_api`) must NEVER execute unbounded queries over `kalai_algolog` or `system_logs`. Always enforce a strict hard limit (`MAX_EXPORT_RECORDS = 25000`, `HARD_MAX_ANALYSIS_LOGS = 25000`). Never load large log datasets as heavy Django ORM model instances with `select_related`; query lightweight `.values(...)` or raw database cursor streams to prevent multi-gigabyte heap bloat and GC starvation.
- **Web ASGI Connection Pool Baseline (Debug vs Production Isolation)**: The web server (ASGI / Uvicorn) connection pool in `settings.py` must differentiate between DEBUG and PRODUCTION modes: (1) In **DEBUG / Local mode**, allocate an expanded pool (`min_size: 1`, `max_size: 6`) to prevent thread and pool starvation (`couldn't get a connection after 10.00 sec`) during interactive developer tasks, parallel browser tabs, and log anomaly analysis; (2) In **PRODUCTION mode**, strictly maintain a lean connection baseline (`min_size: 0`, `max_size: getattr(config, "DB_POOL_MAX", 2)`, `max_idle: 30s`) so idle PostgreSQL backends cleanly terminate, preventing server CPU stress, memory waste, and exhaustion of PostgreSQL `max_connections` (capped at 20-40) across concurrent services (`algo_engine`, `ws_engine`, `django_q`).


## 3. Token Architecture & Database Maintenance Standards
- **Cross-Broker Token Mapping**: Use `BrokerTokenMapper` and `CanonicalInstrumentKey` in [`algo_trading/algos/broker_token_mapper.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/algos/broker_token_mapper.py) for broker-agnostic instrument resolution across Indian and Crypto brokers.
- **Config-Aware Cache Invalidation & Active Subscriptions**: Validate that cached `cum_table` active symbols match runtime configuration symbols (`Capital_share > 0`) using exact set equality (`cached_all_symbols == current_active_symbols`) in `ExchangeMasterData` and broker utilities. Invalidate cached universes immediately if inactive symbols are present or active symbols differ. `init_ref_list` and `index_ref_list` must strictly subscribe to active symbols where `Capital_share > 0` with positive tokens.
- **Throttled Chunked Database Cleanup with Size Checking**: When deleting historical records from high-frequency tables (`system_logs`, `kalai_algolog`, `kalai_processedtickstore`, `django_q_task`), inspect initial and final table sizes via `pg_total_relation_size()` to log reclaimed disk space, enforce relation identifier regex validation (`^[a-zA-Z0-9_]+$`) to prevent SQL injection, and delete in bounded chunks (5,000 rows) with brief sleep pauses (`time.sleep` / `asyncio.sleep`, default: 0.05s) to throttle CPU and prevent lock contention. Support optional size thresholds (`min_size_mb`) to skip tables below target sizes.
- **Raw SQL Stream Table Resolution (`get_broker_stream_table_name`) & Double-Quoting**: In trading engines (`indian_opt_trde_polars.py`, `crypto_opt_trde_polars.py`, `delta_opt_trde_polars.py`, `coinswitch_opt_trde_polars.py`), stream table fallback resolution must strictly invoke `get_broker_stream_table_name(broker_obj.account_id or broker_obj.name)` from `algo_trading.brokers.consumers`. Never manually concatenate `f"{account_id}_stream_kv"`, because `consumers.py` prefixes numeric account IDs with `b_` (e.g. `73270496` $\to$ `b_73270496_stream_kv`). Always enclose the resolved table identifier in double quotes (`f'SELECT data, timestamp FROM "{stream_tbl}"...'`) to guarantee SQL syntax safety across all account permutations.
- **Test Suite Non-Destructive Isolation & Pre-Delete Safety Guard**: Tests (`tests/`) must NEVER execute unconstrained deletions (`Broker.objects.all().delete()`, `BrokerType.objects.all().delete()`, `ApiProvider.objects.all().delete()`, `AlgoInfo.objects.all().delete()`). Tests evaluating empty states or specific permutations must use `unittest.mock.patch` (e.g. mocking `.all()` / `.filter()` to return `.none()`) or scope deletions strictly to isolated test fixtures (`TEST_ACCOUNT_IDS`). Maintain an active `pre_delete` signal guard in [`tests/conftest.py`](file:///c:/Users/Admin/Documents/deltazero26/tests/conftest.py) to block any accidental deletion of live production accounts (`73270496`, `W1NPY`, `HS6525`, `Prvn_coinswitch`).
- **Data Hub Cloud Sync Endpoint Security & Timeout Guard**: The remote cloning endpoint `/api/data-hub/clone/` must be decorated with `@csrf_exempt` when authenticated via `@staff_or_token_required` and superuser credentials, with dedicated Nginx proxy routing configuring `proxy_read_timeout 600s;` to support multi-hour synchronous data syncs. Operational admin dashboard forms (`data_hub.html`) must not use `<input type="password">` for server keys to prevent browser autofill from corrupting `X-Server-Key` authentication headers.

- **Two-Row Responsive Mobile Admin Header**: In Django Admin mobile viewports ($\le 767\text{px}$), `#header` must flex as a structured two-row column (Row 1: `#branding` for Site Title & TOTP/Login badges; Row 2: `#user-tools` for View Site, Change Password, Log Out with top border separation). The toolbar row (`.admin-toolbar-row`) must enforce at least $+45\text{px}$ vertical separation (`margin-top: 12px !important; margin-bottom: 16px !important;`) so the quick filter search input (`#adminFilterInput`) never visually or functionally collides with or obscures user utility tools.
- **Live Remote Git Metadata Synchronization (`get_git_metadata`)**: When querying repository metadata in `get_git_metadata()`, execute a bounded non-blocking background fetch (`git -c safe.directory=* fetch --quiet origin <branch>` with `timeout=6`) before evaluating ahead/behind commit counts via `git rev-list`. This ensures the Deployment Hub dashboard immediately detects and surfaces freshly pushed GitHub commits (`Behind origin/main by X commit(s) — Ready to update`) instead of reporting false `Up-to-date` statuses against stale local cached references.
