# Lightweight Financial Candle Chart Visualizer

The **Lightweight Financial Candle Chart Visualizer** is a high-performance, dark-themed charting workstation integrated into the Django Admin interface. It is engineered for offline, low-latency visual analysis of algorithmic candlestick datasets (`fwd_10_all`, `fwd_30_all`, `day_cdl_all`, etc.) generated by active trading engines.

---

## 1. Architectural Highlights

* **Official TradingView Lightweight Charts Engine (v4)**: Renders pure OHLC candlestick series directly on an HTML5 canvas at 60 FPS without external JavaScript framework bloat.
* **100% Offline & Local DB Driven**: Queries local PostgreSQL database tables (`kalai_algoinfo` and `kalai_exchangemaster`) directly. It makes **zero external HTTP/API requests** to broker servers (Zerodha Kite, Kotak Neo, CoinDCX, CoinSwitch).
* **Strict Debug Mode Enforcement**: Gated strictly to `settings.DEBUG == True`. If accessed when `DEBUG = False`, both the HTML view and the JSON API return HTTP `403 Forbidden`.
* **Comprehensive Symbol Mapping**: Dynamically maps instrument token numbers to human-readable trading symbols (e.g., `NIFTY 50`, `BANKNIFTY26SEP58800CE`, `CRUDEOILM21SEP26FUT`, `BTCUSDT`, `INFY`) by querying `cum_table`, `aug_table`, `nfo_cds_mcx`, `mcx_instrument_data`, and all `ExchangeMasterData` / `AlgoInfo` datasets across 140k+ instrument mappings.
* **Strict Numeric-Only Filtering & Empty Suppression**: Validates complete OHLC candle integrity (`open`, `high`, `low`, `close`, `timestamp`) and strictly filters out instruments with zero data (`count == 0`) or unmapped numeric-only IDs (`sym.isdigit()`), ensuring only clean, human-readable trading symbols appear in the dropdown.
* **Strict `_all` Suffix Table Filtering**: Only algorithmic candle tables ending with `_all` are queried and listed in the dropdown, filtering out internal state tables (`stop_loss_info`, `strike_entry_info`, `{account}_inst_tokens`).
* **Timezone Parity & IST Precision**: Normalizes naive timestamps with `Asia/Kolkata` for Indian brokers (and UTC for crypto) on the backend before deriving Unix epoch seconds, and renders on frontend Lightweight Charts using `timeZone: "Asia/Kolkata"` to guarantee exact IST crosshairs, axis ticks, and HUD dates without Docker UTC offset shifts.
* **Strict Broker Account Isolation**: When a specific `account_id` is queried, the API strictly returns data for that broker and disables cross-account fallbacks, ensuring empty or newly configured brokers never display another broker's data.
* **Pure `last_price` OHLC Derivation**: Candlesticks are computed strictly from executed trade `last_price` ticks. Any broker-provided 24-hour summary `open`/`high`/`low`/`close` rolling extremes (such as Delta Exchange's 24h ticker extremes) are stripped prior to aggregation, preventing single 10-minute candles from showing false multi-thousand dollar daily spikes.
* **Multi-Interval Warmup & 25+ Bar Parity**: On engine startup, `fetch_recent_ticks` fetches up to 120,000 historical ticks from `ProcessedTickStore`. The engine dynamically downsamples multi-hour batches via `group_by_rolling_window()`, guaranteeing at least 25 continuous historical bars per instrument upon opening the visualizer.
* **Zero Volume & Pure Price Action**: Kept ultra-lightweight and distraction-free with pure OHLC candle series (no volume plots, no Heikin-Ashi conversions).

## 3. URL Routing & Endpoints

All visualizer routes are registered under `AccountAdmin.get_urls()`:

| URL Pattern | View Function | Method | Description |
| :--- | :--- | :--- | :--- |
| `kalai/broker/candle-visualizer/` | `candle_visualizer_view` | `GET` | Renders the HTML workstation and pre-populates account, table, and symbol dropdowns. |
| `kalai/broker/candle-visualizer/api/data/` | `candle_visualizer_api_view` | `GET` | Returns sanitized, deduplicated, ascending chronological OHLC JSON data. |

### API Parameters

* `account_id` *(optional)*: The broker account identifier (e.g. `HS6525`). Defaults to the first available broker.
* `tablename` *(optional)*: The target candle table ending with `_all` (e.g. `fwd_10_all`, `fwd_30_all`, `day_cdl_all`). Defaults to `fwd_10_all`.
* `token` *(optional)*: The specific instrument token or symbol name. Defaults to the first available instrument in the candle table.

## 4. Backend Implementation Mechanics

### Symbol Resolution (`_get_symbol_map_for_broker`)
The `AccountAdmin._get_symbol_map_for_broker(broker)` helper extracts token-to-symbol mappings:
1. Queries `cum_table` from `ExchangeMasterData.get_master(account=broker, master_name="cum_table")`.
2. Inspects auxiliary datasets (`aug_table`, `nfo_cds_mcx`, `coindcx_market_details`).
3. Safely extracts records whether returned as raw Python `list`/`dict` datasets or model instances.
4. Maps `instrument_token` / `Ref_stock_tkn` integers to clean `tradingsymbol` / `Symbol` / `name` strings.

### Timestamp Normalization & Ascending Sort
TradingView Lightweight Charts strictly requires epoch second timestamps in unique, strictly ascending chronological order. `candle_visualizer_api_view` sanitizes candle records:
- Parses ISO-8601 strings, `YYYY-MM-DD HH:MM:SS`, and epoch timestamps.
- Deduplicates identical timestamps (`deduped[c["time"]] = c`).
- Sorts ascending by epoch time (`final_candles.sort(key=lambda x: x["time"])`).

### Pure `last_price` Aggregation & Multi-Interval Resampling
Candles served by the visualizer are generated by `algo_trading/algos/indian_candle_engine.py`:
- **Isolation from 24h Summary Extremes**: In multi-asset feeds, broker tick payloads often embed exchange-level 24-hour summary extremes (`open`, `high`, `low`, `close`). The engines explicitly strip these summary columns from raw tick frames. `group_by_rolling_window()` prioritizes `last_price` above all else, calculating open (first tick), high (max tick), low (min tick), and close (last tick) exclusively from executed trade prices within that interval.
- **Multi-Interval Bootstrap Delegation**: When the trading engine starts up or when historical bars are fewer than 25, `update_candles_incremental()` detects that the incoming tick span exceeds a single bar window (`dt_span > window_sec`) and automatically delegates to `group_by_rolling_window()`, cleanly slicing up to 120,000 historical ticks into at least 25 continuous bars across all timeframes (`fwd_10_all`, `fwd_30_all`, `day_cdl_all`, etc.).

## 5. Connection Pooling Optimization

To ensure concurrent dashboard requests, asynchronous ASGI channels, and the visualizer operate smoothly without pool starvation:
- **`DB_CONN_POOL_SIZE`**: Increased default from `2` to `10` in [`algo_trading/app_config.py`](../app_config.py).
- **`OPTIONS.pool`**: Configured with `min_size: 1`, `max_size: 10`, `timeout: 10.0`, and `max_idle: 300` in [`algo_trading/settings.py`](../settings.py).
