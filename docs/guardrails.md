# System Architecture Guardrails: Engineering Standards & Operational Rules

This document establishes the universal architecture principles, coding standards, performance benchmarks, and operational guardrails for **DeltaZero26**. These rules are generic, broker-agnostic, and apply to all strategies, broker feeds, streaming engines, database interactions, and deployment environments across the platform.

---

## 1. High-Performance Strategy Engine Standards

DeltaZero26 is designed for low-latency execution on resource-constrained cloud environments. Strategies must execute within tight time budgets without memory bloat.

###  DO
- **Pure Vectorized High-Performance Compute (Pure Polars)**: Build all analytical, candle aggregation, indicator logic, and spreadsheet ingestion using native **Polars + openpyxl** with zero Pandas runtime dependencies.
- **Deterministic Synchronous Sequential Strategy Pipeline**: Execute strategy cycles sequentially across active accounts every 2.0 seconds (`run_algos_sequential`), eliminating coroutine context switching, thread-hopping, and database connection churn.
- **Single-Pass Macro Candle Resampling**: Execute multi-token, multi-timeframe candle downsampling (`update_all_candles_batch`) strictly once per trading loop cycle at the macro engine level (`trde()`) before iterating over tokens in `mom()`.
- **Precomputed Buffer Slicing in `mom()`**: Slice token-specific candle series directly from pre-computed, zero-copy global Arrow buffers (`fwd_1_all` to `fwd_60_all`, `day_cdl_all`, `half_day_cdl_all`) inside `mom()` to achieve sub-millisecond evaluation per instrument.
- **Monotonicity Evaluation in Descending Series**: Candle buffers in memory are sorted in descending chronological order (`date_time` descending, index `0` = latest candle). Evaluate monotonicity using scalar Python comparisons (`fwd10_mean[0] >= fwd10_mean[1]` for rising price / `is_monotonic_decreasing` index parity; `fwd10_mean[0] <= fwd10_mean[1]` for falling price / `is_monotonic_increasing` index parity) or generator expressions (`all(...)`) for $O(1)$ fast evaluation.
- **Early Ingestion Filtering (`build_aug_table`)**: Filter candidate instruments at the earliest configuration ingestion boundary via `build_aug_table(stock_data_info)` in [`polars_excel.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/algos/polars_excel.py), strictly requiring `Capital_share > 0` and `Max_lots_per_order > 0`. Completely ignore `Tradable_stock` (pending future deprecation/removal). Discard zero-capital underlyings before master contract assembly, candle downsampling, strike calculations, or WebSocket subscriptions occur.
- **Explicit Static Master Strategy Registry**: Register strictly the production unified master engines (`indian_opt_trde_polars.py` and `crypto_opt_trde_polars.py`) inside `load_all_algos()` in [`algo_trading/algos/__init__.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/algos/__init__.py). Standalone engines (`zerodha_opt_trde_polars.py`, `kotak_opt_trde_polars.py`, `coinswitch_opt_trde_polars.py`, `delta_opt_trde_polars.py`) must remain excluded from `load_all_algos()` to prevent duplicate executions and logging cross-talk.
- **Lazy Module Loading in Registry**: Import strategy functions inside the `load_all_algos()` function to prevent top-level circular imports with the `@algo` strategy decorator.
- **In-Memory Native Dictionaries for Fast State**: Store high-frequency state, debounce counters, and tracking maps in native Python dictionaries (`Dict[int, int]`, `Dict[str, Any]`) to achieve sub-microsecond $O(1)$ lookups and zero allocation overhead.
- **Dynamic Dtype Safety**: Support fractional asset prices, decimal strike values, and step-rounded lot quantities (`Float64` / `Int64`) safely without hardcoded `int()` truncations.
- **Numeric Dtype Casting at Config Ingestion Boundary**: Explicitly cast `cap_config` columns (`tradable`, `minimum_lots_to_buy`, `maximum_lots_to_buy`, `preference` → `Int64`; `lower_price_limit`, `upper_price_limit` → `Float64`) to proper numeric dtypes immediately after loading from Excel via `openpyxl` in [`polars_excel.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/algos/polars_excel.py) (both `load_indian_algo_config` and `load_crypto_algo_config`), and after joining `cap_config` into `cum_table` in [`indian_master_tokens.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/algos/indian_master_tokens.py) and [`crypto_master_tokens.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/algos/crypto_master_tokens.py). This prevents `openpyxl` string-typed values (e.g. `tradable = '1'`) from causing silent logic failures in downstream comparisons.
- **Defensive `tradable` Type Coercion in Execution Loops**: Before evaluating `tradable != 1` buy-gate conditions in strategy engines, always cast the raw `tradable` value to `int` via safe parsing (`int(float(str(tradable_val).strip()))`) with `try...except` fallback to `0`. Never compare raw Excel-sourced values directly against integer literals, as `openpyxl` may return strings, floats, or `None`.
- **`algo_dir` Fallback Input File Resolution**: In unified strategy engines ([`crypto_opt_trde_polars.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/algos/crypto_opt_trde_polars.py), [`indian_opt_trde_polars.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/algos/indian_opt_trde_polars.py)), resolve `input_file` paths by first checking `data_file_path` (project root), then falling back to `algo_dir` (`os.path.dirname(os.path.abspath(__file__))`) where Excel config files actually reside. This ensures correct resolution inside Docker containers where `data_file_path` is `/app/` but config files are at `/app/algo_trading/algos/`.
- **`AlgoInfo` Database Sync & Token Subscription Parity**: Production strategy engines (`crypto_opt_trde_polars.py`, `indian_opt_trde_polars.py`) must maintain complete state persistence parity in the `kalai_algoinfo` database table. Specifically: (1) persist subscribed tokens to `{account_id}_inst_tokens` via `broker.set_subscribed_tokens(sym_list)` so streaming feeds dynamically subscribe to genuine contracts, (2) persist resampled multi-timeframe candles (`fwd_10_all`, `fwd_30_all`, `fwd_60_all`, `day_cdl_all`) via `broker.set_algo_state()` using in-memory deduplication caching (`_candle_cache`) to avoid redundant writes, and (3) persist parsed Excel configuration tables (`stock_config`, `stock_data_info`, `cap_config`) via `update_config_info()`. Target brokers for persistence (`_get_target_brokers()`) must strictly filter for active accounts where `enable_trade=True`. Accounts with `enable_trade=False` must never receive candle arrays, token table subscriptions, or config snapshots in `kalai_algoinfo`.
- **Unified Multi-Broker SIMD & Incremental O(1) Candle Engine (3m Base)**: Both Indian (`indian_opt_trde_polars.py`) and Crypto (`crypto_opt_trde_polars.py`) master engines delegate candle updates exclusively to `algo_trading/algos/indian_candle_engine.py`: (1) In raw ticks, `last_price` is strictly prioritized over broker-provided summary `open`, `high`, `low`, and `close` fields (which often contain 24-hour daily rolling extremes); any summary OHLC columns in raw ticks are stripped prior to aggregation; (2) On cold start or startup warmup, multi-token batch downsampling is bootstrapped via `group_by_rolling_window()`; (3) In active 2-second trading loops, incoming ticks are downsampled directly into 3-minute base candles (`fwd_3_all`), eliminating intermediate 1-minute memory buffers and allocations. Only the single active (latest) 3-minute bar per token (`active_3m`, $O(1)$) is extracted and passed to `update_candles_incremental()` to update higher timeframes (`fwd_5_all`, `fwd_10_all`, `fwd_15_all`, `fwd_30_all`, `fwd_60_all`, `day_cdl_all`). Within the active time bucket, the latest candle's `close`, `high`, and `low` are updated in place; when the timeframe delta elapses, a new candle is created where `open` strictly equals the previous candle's `close`. Each token retains at least 25 bars (`MAX_CANDLE_HISTORY_BARS`), eliminating 1,500-bar memory buffers. Historical session context is preserved across date boundaries, and stale/expired contracts are evicted via time-horizon filtering.
- **Continuous Candle Lifecycle, Startup Warmup & EOD Persistence**: On engine initialization, `read_db_candle()` restores historical multi-timeframe candles (`fwd_10_all`, `fwd_30_all`, `fwd_60_all`, `day_cdl_all`, `prev_day_cdl_all`) from `kalai_algoinfo` without discarding records due to calendar date differences, and warms up from `ProcessedTickStore` (via `fetch_recent_ticks(seconds=None, limit=120000)`) if available. On EOD or date rollover, `check_eod_cleanup()` preserves `day_cdl_all` into `prev_day_cdl_all` in DB and clears raw tick buffers, but strictly preserves multi-timeframe candle tables in DB (never resetting them to `[]`) so chart visualizers and strategy warmups have immediate candle data at next market open.
- **Lean Active Timeframe Downsampling (3m Base)**: Resample and buffer strictly the timeframes actively consumed by signal decisions (`3m` base & strike midpoint, `10m` momentum indicators & `ref_min_max_all`, `30m` trend structures, `60m`, `1D` daily close). Omit intermediate 1m allocations to eliminate redundant memory and CPU overhead.
- **Per-Token History Capping (`MAX_CANDLE_HISTORY_BARS`)**: Enforce history limits strictly per instrument token via `.group_by('instrument_token').head(max_bars)` (default: 25 bars) to prevent unbounded memory growth while guaranteeing uniform lookback coverage across all tokens.
- **Instrument Precision Normalization**: Normalize tick sizes, step sizes, and price increments using market specification metadata across equity, derivative, forex, and crypto markets.
- **Unified Cross-Broker Token Architecture**: Normalize trading symbols, derivative contracts (options/futures), expiries, and cash index aliases using `CanonicalInstrumentKey` and `BrokerTokenMapper` ([`broker_token_mapper.py`](file:///c:/Users/Admin/Documents/deltazero26/algo_trading/algos/broker_token_mapper.py)). Ensure underlying references map to genuine broker contract IDs (e.g. `27` for Delta `BTCUSD`), avoiding pseudo-hashes or malformed string concatenations.
- **Config-Aware Crash Recovery & Dynamic Cache Invalidation**: When restoring pre-computed instrument universes (`cum_table`) from `ExchangeMasterData`, validate that cached active symbols match current runtime configuration symbols (`Capital_share > 0`) using exact set equality (`cached_all_symbols == current_active_symbols`). If inactive symbols are present or active symbols differ, invalidate the cache immediately and assemble fresh tokens. Dynamically synchronize current `Capital_share` weights into cached tables upon restoration.
- **Strict Active Subscription Filtering**: In `init_ref_list` and `index_ref_list`, filter strictly for positive integer tokens (`> 0`) where `Capital_share > 0`. Never subscribe to inactive contracts or symbols configured with zero capital allocation.
- **Lean Strategy Token Delegation**: Delegate `master_tkn_list` resolution in strategy engines (`TradeAlgo`) to broker utility classes (`ZerodhaUtility`, `KotakNeoUtility`, `DeltaUtility`, `CoinSwitchUtility`, `CoinDCXUtility`) to keep algorithm scripts lean, maintainable, and decoupled from raw broker APIs.
- **Resilient Broker Utility Discovery Mode**: Broker utilities must initialize gracefully without throwing uncaught exceptions when credentials or access tokens are missing or unconfigured in the database. Public discovery methods (`master_tkn_list()`, `instruments_list()`, `get_ticker()`, `get_products()`) must operate unhindered, while authenticated operations (`mrk_ordr()`, `chk_live_bal()`, `pos_data()`) must be guarded and return structured error codes (`-1`) or safe empty defaults (`0.0, 0.0` / `None, None`).
- **Fail-Fast Network Retry with Exponential Backoff**: API retry helpers (`retry()`) in broker utility wrappers must immediately raise and fail fast on unrecoverable authentication errors (HTTP 401, HTTP 403, `TokenException`, expired/invalid signatures) rather than executing redundant backoff retries.
- **Pure Polars Interoperability in Utilities**: All utility methods returning tabular data (`holdings()`, `pos_data()`, `instruments_list()`) must return native Polars DataFrames (`pl.DataFrame`). Never call Pandas-only methods or attributes (`.empty`, `.iloc`, `.ix`) on Polars objects; always use `.is_empty()` and bracket row/column slicing.
- **Separation of Universe Assembly (`load_master_token_list`) and Minimal Active Subscriptions (`token_list_update`)**: Keep master contract universe loading (`cum_table` & `inst_list_int`, 900+ rows) strictly distinct from active data feed subscriptions. Only subscribe the minimal active set assembled by `token_list_update()`: underlying reference symbols (`init_ref_list`), index tokens, active positions/holdings, and dynamically selected ATM/OTM options (`Buy_strike == 'Yes'`) (~8 to 15 tokens total).
- **Strike Detection Expiry Cutoff & Distance Offsets**: In `strike_detect()` / `detect_strike_side()`, always add `Strike_dist_CE` and `Strike_dist_PE` offsets to candle averages ($\text{est\_strike} = \text{candle\_avg} + \text{Strike\_dist}$), filter options strictly with `expiry > tomorrow` (`expiry > today + 1 day`) and `exp_date_list > month_cutoff`, and enforce `cap == cap_info` before finding the minimum week distance (`min_week`). `execute_trade_cycle()` must dynamically invoke `token_list_update()` and `insert_instrument_token()` in each execution cycle to maintain live feed synchronization.
- **Per-Symbol Rate Limiting in `BaseFeed`**: In `BaseFeed.enqueue_tick()`, track rate-limit timestamps per symbol slot (`self._last_tick_times: dict[str, float]`) at `rate_limit_interval = 0.1` (100ms per symbol). High-throughput instruments like `BTCUSD` or `NIFTY 50` must never starve secondary underlyings or active option strikes.
- **Resilient Strike Detection Price Resolution**: Never skip underlying strike detection if recent ticks are empty (`if recent_ticks.is_empty(): continue` is forbidden). Instead, calculate `candle_avg` hierarchically: (1) 3-minute candle midpoint (`ref_fwd_3`), (2) latest tick price (`recent_ticks['last_price'][-1]`), (3) contract reference price in master universe (`matching_ref['last_price'][0]`), (4) daily candle close (`day_cdl_all`) or base price fallback (`KNOWN_CRYPTO_BASE_PRICES`). Round distance ratios (`round(6)`) before evaluating `ratio >= 1.0` (CE) and `ratio <= 1.0` (PE) to prevent floating-point inequality at ATM boundaries.
- **Forward Option Chain Synthesis for Underlyings Lacking Exchange Options**: In `assemble_crypto_cum_table()`, detect underlyings in `aug_table` that lack forward options expiring strictly after tomorrow (`expiry > tomorrow`) (e.g., SOL, XRP, and daily-only ETH on Delta Exchange India). Synthesize standardized CE and PE option chains centered around base price across weekly/monthly expiries to ensure all configured underlyings select 1 CE + 1 PE strike, yielding $(N \text{ underlyings} + 2N \text{ strikes} = 12 \text{ tokens for } N=4)$ in `{account_id}_inst_tokens`.
- **Non-Truncating Tick Ingestion & 120k Warmup Limit**: `fetch_recent_ticks()` must not drop historical ticks with an arbitrary 180-second hard cutoff. When `seconds` is omitted (`seconds=None`), fetch the most recent available ticks per instrument from `ProcessedTickStore` or partitioned stream tables (up to 120,000 ticks during engine warmup) so that multi-instrument portfolios have sufficient history to bootstrap at least 25 continuous bars across all timeframes.
- **Public Client Parameter Support**: All broker utility `__init__` signatures must accept `client: Any = None` to facilitate dependency injection, mock testing, and isolated execution without live network or database access.

###  DO NOT
- **DO NOT Calculate Candles from Broker Summary 24-Hour OHLC Fields**: Raw market ticks must NEVER use broker-provided summary `open/high/low/close` fields (such as Delta Exchange's 24h rolling extremes), which corrupt individual 1m, 3m, 10m, and 30m candles with daily price swings of \$1,000+. Candles must strictly derive Open, High, Low, and Close from executed trade `last_price` ticks within that timeframe window.
- **DO NOT Subscribe Full Universes (`cum_table` / `inst_list_int`) to Streaming Feeds**: Never pass all `tradingsymbol` values from `cum_table` or `inst_list_int` directly to `insert_instrument_token()` or `broker.set_subscribed_tokens()`. In the reference implementation, `inst_list_int` was solely used for sizing internal counter matrices. Subscribing 900+ contracts overloads WebSocket feeds with thousands of redundant channels (`ticker`, `all_trades`, `l2_orderbook`), exceeds broker rate limits, and spikes latency.
- **DO NOT Run Strike Detection Without Expiry Boundaries (`expiry > tomorrow`)**: Never evaluate `min_week = candidates['week_dist'].min()` without first filtering out expired or same-day options (`expiry > today + 1 day`). In crypto options, same-day expiring contracts often have narrow strike bands that do not span current spot prices, causing ATM/OTM filters to return empty and silently preventing valid strike selection.
- **DO NOT Place Batch Resamplers Inside Signal/Token Loops**: Never invoke batch candle resamplers (`update_all_candles_batch`) or defensive fallback resampling checks inside per-token signal evaluation methods (`mom()`). Doing so causes $O(N \times \text{resampling})$ redundant calculations and severely degrades per-cycle performance.
- **DO NOT Use `.diff().gt_eq(0).all()` Expressions for Small Candle Monotonicity**: Never construct Polars Series and `.diff()` expressions for 2-to-4 element candle monotonicity checks. Polars `.diff()` produces a leading `null` at index 0, causes false positives on missing data with `.all()`, risks inverted buy/sell signal triggers on descending candle series, and introduces heavy object allocation overhead compared to native scalar comparisons.
- **DO NOT Rely on `Tradable_stock` for Ingestion or Tradability**: Never use `Tradable_stock` to decide tradability. Ingestion and universe assembly must strictly rely on `Capital_share > 0` and `Max_lots_per_order > 0`.
- **DO NOT Compare Raw Excel Config Values Against Integer Literals Without Type Coercion**: Never write `if tradable != 1` or `if tradable == 1` directly against values loaded from `openpyxl` / Polars ingestion without first casting to `int`. Excel cells may return `'1'` (string), `1.0` (float), or `True` (bool), all of which fail strict `!= 1` integer comparison and silently skip every candidate in the buy loop.
- **DO NOT Hardcode Input File Paths to Project Root Only**: Never resolve `token_ref.xlsx` or `token_ref_bitcoin.xlsx` exclusively from `data_file_path` (project root) without an `algo_dir` fallback. In Docker containers, config files reside under `algo_trading/algos/`, not the project root (`/app/`). Missing input files cause empty `aug_table` initialization, zero-token assemblies, and silent order placement failures.
- **DO NOT Resurrect Inactive Symbols on Empty Ingestion**: Never write fallback logic that reverts to unfiltered symbol lists or resurrects zero-capital symbols if `aug_table` becomes empty; if no symbols have positive capital, return a clean empty DataFrame.
- **DO NOT Import Standalone Legacy Strategies in `load_all_algos()`**: Never import standalone engines (`coinswitch_opt_trde_polars`, `delta_opt_trde_polars`, `kotak_opt_trde_polars`, `zerodha_opt_trde_polars`) inside `load_all_algos()`. Importing them executes their `@algo` decorator registrations and triggers duplicate runner executions.
- **DO NOT Allocate Intermediate DataFrames for Counters**: Never create or concatenate DataFrames to store or increment scalar counters. Allocating DataFrames on every iteration causes memory fragmentation, CPU spikes, and garbage collection pauses.
- **DO NOT Use Dynamic Runtime Module Scanning**: Avoid runtime directory scanning (`pkgutil.iter_modules()`) for loading production algorithms. It introduces hidden failure modes, non-deterministic load orders, and uninspected background executions.
- **DO NOT Re-enable Legacy Inefficient Implementations**: Keep legacy, unoptimized, or reference implementations disabled in production environments.
- **DO NOT Perform Circular Top-Level Imports**: Never import strategy modules at the root level of the registry module if those strategies import decorators from the registry.
- **DO NOT Persist Candles or Token Subscriptions for Inactive/Disabled Accounts**: Never write `AlgoInfo` state records, `{account_id}_inst_tokens`, or candle tables for accounts where `enable_trade=False`. State persistence gating must verify `enable_trade=True` in `_get_target_brokers()` to avoid orphan rows, state confusion, and unnecessary database write overhead for dormant brokers.

## 2. Multi-Account Context & Unified Logging Standards

DeltaZero26 operates as a multi-tenant, multi-broker platform. Log records and telemetry must be strictly attributed to the executing account.

###  DO
- **Static Module-Level Algorithm Identity (`_CURRENT_ALGO_NAME`)**: Define an explicit static constant `_CURRENT_ALGO_NAME` in every algorithm engine (e.g. `"zerodha_opt_trde_polars"`, `"kotak_opt_trde_polars"`, `"coinswitch_opt_trde_polars"`), and bind it in `_db_insert_single_log` and `algo_logger.set_active_account(broker, algo_name=...)`.
- **Post-Validation Active Account & Algorithm Context Binding**: Explicitly bind `algo_logger.set_active_account(broker_obj, algo_name=_CURRENT_ALGO_NAME)` **strictly after** validating broker compatibility (e.g. verifying broker asset class and account support) to guarantee thread-isolated logging context without premature context pollution.
- **Guaranteed Context Teardown (`try...finally`)**: Enclose strategy execution bodies and sequential loop account passes in `try...finally: algo_logger.clear_active_account()` to ensure that thread context is guaranteed to reset upon iteration completion, return, or exception.
- **System Registry Context Reset**: Call `algo_logger.clear_active_account()` at the start of `load_all_algos()` so that platform-level strategy discovery, status checks, and skipping logs are recorded as clean unassigned system logs without inheriting prior account identities.
- **Throttled Registry Change Logging & Loop Caching**: Emit `load_all_algos()` status messages at `INFO` only when the active algorithm list changes; keep cycle-by-cycle candidate skipping diagnostics at `DEBUG` with domain groupings. Pass cached `algos=REGISTERED_ALGOS` to `run_algos_sequential()` in execution loops, reloading only when active accounts change.
- **Framework Registry Log Isolation**: Keep `load_all_algos()` candidate discovery logs isolated to standard library logging (`_logger.debug()`). `InterceptDBLogHandler` must explicitly ignore records from `algo_trading.algos` and `load_all_algos`, and must drop `DEBUG` records to prevent framework noise from polluting `kalai_algolog`.
- **Unassigned Log Attribution to SYSTEM**: Any system, lifecycle, or framework log where neither active context nor specific algorithm name can be determined must be assigned to `"SYSTEM"`, never falling back blindly to `"indian_opt_trde_polars"`.
- **Target Strategy Domain Filtering**: Support filtering candidate algorithms by domain (`load_all_algos(target_strategy='indian' | 'crypto')`) to restrict auto-discovery to relevant market domains when requested.
- **Dual-Authentication with Dedicated `M2M_SERVER_KEY` (`@staff_or_token_required`)**: Protect all administrative log, tick, and model export APIs with dual authentication supporting both interactive staff user sessions and constant-time M2M cryptographic bearer tokens (`X-Server-Key` / `Authorization: Bearer <M2M_SERVER_KEY>`), isolating programmatic export access from Django's core `SECRET_KEY`.
- **Strict TLS Verification in Remote Synchronization**: Enforce verified SSL/TLS certificates via `SSL_VERIFY` (`requests.get(..., verify=SSL_VERIFY)`) for outbound data ingestion and model synchronization calls, while allowing explicit override via UI toggle ("Accept Self-Signed SSL"), CLI flag (`--insecure`), or `.env` (`SSL_VERIFY=false`) when accessing cloud servers directly via IP address or self-signed development certificates.
- **Cross-Environment Foreign Key Remapping in Cloud Sync**: Never rely on raw integer auto-increment primary keys (`account_id = 1`) during cross-database data synchronization. All foreign key references must be resolved via `_build_remote_broker_map()` using canonical string account identifiers, token tablenames (`{account_id}_inst_tokens`), or asset class symbol heuristics (`BTC` $\to$ Crypto, `NIFTY` $\to$ Indian). Ingest records via idempotent domain model methods (`save_master`, `create_or_update`, `update_or_create`) rather than raw `obj.save()`, and gracefully fall back to `None` for nullable relationships to prevent foreign key constraint violations.
- **Explicit Cloud-Fetch Failover**: When operating as a client in Local/Debug mode, log export actions must attempt synchronization from the remote cloud server (`SERVER_IP`). If the remote server is unreachable, firewalled, or returns an error, the operation must fail explicitly with structured error feedback (`HTTP 502`) and structured connection timeouts (`timeout=(4.0, 30.0)`).
- **ISO-8601 Timestamp Standard**: Attach a standardized ISO-8601 timestamp prefix `[{datetime.now().isoformat()}]` to every log message upon creation across all log handlers and subsystems.
- **In-Memory Buffering & Periodic Batch Flushing**: Buffer algorithm and system log entries in memory (`_IN_MEMORY_LOG_BUFFER`) and write them to the database in batches (`LOG_BATCH_SIZE_LIMIT`) or at regular intervals (`LOG_FLUSH_INTERVAL`) via `flush_if_needed()`.
- **Active-Broker Fallback Resolution**: When resolving broker instances for fallback or startup logging, explicitly filter for active, enabled accounts (`Broker.objects.filter(enable_trade=True)`) before any generic fallback. If no broker is active, log with `broker=None` rather than arbitrarily picking a row.
- **Thread-Safe Log Collection**: Ensure log buffer appends and exports are protected by threading locks (`_LOG_BUFFER_LOCK`) to guarantee thread and async safety.
- **Strict Thread-Local Context**: Active account and algorithm name context in `ActiveAlgoContext` must be strictly thread-local (`threading.local()`) without global fallback references (`self.default_account`), preventing cross-account and cross-thread log bleeding.
- **ThreadPool Worker Context Propagation**: When spawning worker threads via `ThreadPoolExecutor` (e.g. in `CryptoUserAccount.sync_account_state` or `IndianUserAccount.sync_account_state`), always propagate account and algorithm context to worker tasks using a context wrapper with guaranteed cleanup (`try...finally: algo_logger.clear_active_account()`).
- **Account Identifier Log Inference & Engine Alignment**: When logging errors mentioning specific broker accounts without an explicitly passed `Broker` object, `algo_logger.log_sync` automatically extracts candidate account identifiers to resolve the exact `Broker` instance and aligns the algorithm identity based on broker class (crypto vs Indian).
- **Conclusive Return Logging & Decision Transparency**: All algorithmic methods in unified strategy engines (`indian_opt_trde_polars.py`, `crypto_opt_trde_polars.py`) must emit an informative log immediately before every `return` statement (including early-exit guards, input validation rejections, and completion summaries). Crucial algorithmic branch decisions must use standardized, traceable prefix tags (`[ORDER_GATE]`, `[ORDER_STATUS]`, `[ALGO_GATE]`, `[CYCLE_SUMMARY]`, `[MOM_SIGNAL]`, `[DERIV_ANALYSIS_COMPLETE]`, `[TRADE_LOOP_SUMMARY]`, `[SLU_SUMMARY]`, `[ORDER_PENDING_SUMMARY]`, `[MARKET_SIGNALS]`).
- **Bounded Log Querying & Values Ingestion (`kalai_algolog`)**: Diagnostic views, anomaly analyzers (`LogAnomalyAnalyzer`), and export utilities (`process_and_export_algo_logs`, `export_algo_logs_api`) must NEVER execute unbounded queries over `kalai_algolog` or `system_logs`. Always enforce a strict hard limit (`MAX_EXPORT_RECORDS = 25000`, `HARD_MAX_ANALYSIS_LOGS = 25000`). Never load large log datasets as heavy Django ORM model instances with `select_related`; query lightweight `.values(...)` or raw database cursor streams to prevent multi-gigabyte heap bloat and GC starvation.
- **Web ASGI Connection Pool Baseline (Debug vs Production Isolation)**: The web server (ASGI / Uvicorn) connection pool in `settings.py` must differentiate between DEBUG and PRODUCTION modes: (1) In **DEBUG / Local mode**, allocate an expanded pool (`min_size: 1`, `max_size: 6`) to prevent thread and pool starvation (`couldn't get a connection after 10.00 sec`) during interactive developer tasks, parallel browser tabs, and log anomaly analysis; (2) In **PRODUCTION mode**, strictly maintain a lean connection baseline (`min_size: 0`, `max_size: getattr(config, "DB_POOL_MAX", 2)`, `max_idle: 30s`) so idle PostgreSQL backends cleanly terminate, preventing server CPU stress, memory waste, and exhaustion of PostgreSQL `max_connections` (capped at 20-40) across concurrent services (`algo_engine`, `ws_engine`, `django_q`).

### 🚫 DO NOT
- **DO NOT Allow Silent Early Returns in Algorithmic Routines**: Never return `None`, `-1`, or empty DataFrames (`pl.DataFrame()`) from strategy methods on guard condition failures (`if not acc or not acc.enabled: return`) without logging an informative diagnostic message explaining the exact reason for the exit. Silent exits mask configuration issues and make algorithm behavior unobservable.
- **DO NOT Load Unbounded Log Queries as Django ORM Models**: Never iterate over `AlgoLog.objects.all()` or `select_related('account')` without strict limit slicing and `.values()`. In high-frequency trading platforms with millions of log rows, hydrating millions of ORM models into Python memory triggers 4+ GB RAM consumption, locks the process in GC thrashing, and starves database connection pools.

- **Multi-Threaded Test Database Isolation (`transaction=True`)**: When testing functions that spawn background worker threads (`ThreadPoolExecutor`, `threading.Thread`) interacting with database models, always use `@pytest.mark.django_db(transaction=True)`. Standard Django test atomic transactions are thread-local; without `transaction=True`, worker threads open separate database connections that cannot see uncommitted test rows, triggering false foreign key violations.
- **Comprehensive Master Segment Resolution**: When resolving instrument tokens for segment-dependent brokers (like Kotak Neo), always inspect both `ExchangeMasterData` (`cum_table`, `aug_table`, `mcx_instrument_data`) and `AlgoInfo` across account and global tables to ensure commodity (MCX) and regional (BSE) contracts are correctly mapped to their respective exchange segments (`mcx_fo|...`, `bse_cm|...`) rather than blindly assuming `nse_fo`.
- **Bounded WebSocket Subscription Batching**: Chunk large symbol subscription lists into bounded batches (e.g. 50–100 symbols per frame) in WebSocket feeds (e.g. `DeltaExchangeFeed`) to prevent WebSocket gateway frame size overflows.
- **Spot Pair Normalization for Crypto Sockets**: In spot Socket.IO streaming engines (like `CoinSwitchFeed`), always normalize and deduplicate option contract identifiers down to their base trading pairs (`BTC,USDT`, `ETH,USDT`) to prevent flooding the socket with thousands of redundant strike emissions.

### 🚫 DO NOT
- **DO NOT Allow Cascading Failures Across ThreadPool Endpoints**: Never retrieve multiple thread futures sequentially without per-future error handling. If `futures['holdings'].result()` raises an unhandled exception, it aborts the entire synchronization cycle and leaves balance and positions stale.
- **DO NOT Assume Non-Zero `lot_size` or `tick_size`**: Never divide by raw values from metadata tables without `max(1, ...)` or `max(0.01, ...)` protection. Corrupted or uninitialized broker contract metadata containing 0 will trigger immediate `ZeroDivisionError` crashes.
- **DO NOT Let One Expired Account Kill the Multi-Broker Engine**: Never iterate over active accounts with bare utility creation calls that propagate exceptions to the process level.
- **DO NOT Call `float()` Directly on Nullable Series Elements**: Never write `float(series[0])` without checking for `None` or using `or 0.0`.
- **DO NOT Skip Candle Timeframes Expected by Subsystems**: Never omit intermediate resampling windows (`fwd_5_all`, `fwd_15_all`) from `update_all_candles_batch`; keep downsampling sets symmetrical and complete.
- **DO NOT Assume Token Numbers Above 20,000 are Exclusively `nse_fo`**: Never use simple numeric thresholds without consulting `ExchangeMasterData` datasets, as MCX commodity tokens and BSE scrip codes frequently fall into the 200,000–900,000 range.
- **DO NOT Emit Thousands of Individual Socket Subscriptions in Loops**: Never loop over hundreds of derivative contracts emitting individual socket events without deduplication and batching.

## 9. Deployment & Operational UI Standards

Robust operational interfaces and out-of-container deployment pipelines require strict handling of authentication tokens, process concurrency, database startup states, and responsive viewports.

###  DO
- **Defensive API Client Response Parsing**: In admin workstation JavaScript, always verify `res.headers.get("content-type")?.includes("application/json")` before calling `await res.json()`. If the backend returns an HTML error page (such as 403, 500, or 502), extract the status and text to display a clear error message rather than throwing an unhandled `JSON.parse` syntax error.
- **CSRF Token Dual-Resolution**: Pass valid CSRF tokens via `X-CSRFToken` headers using both DOM elements (`[name=csrfmiddlewaretoken]`) and cookie fallbacks (`csrftoken`), while decorating authorized M2M/staff endpoints with `@csrf_exempt` when secured by `@staff_or_token_required` and superuser role validation.
- **Active Database Readiness Wait Loop**: When orchestrating container restarts or deployments via `deploy.sh`, always poll `pg_isready -h 127.0.0.1 -p 5432` in a loop before running `python manage.py migrate`. This eliminates database startup race condition failures (`FATAL: the database system is starting up`).
- **Clean-Slate Deployment Logging**: Truncate deployment log files (`open(DEPLOY_LOG_FILE, "w")` / `tee "$LOG_FILE"`) and reset client byte offsets (`logOffset = 0`) at the initiation of each new deployment job, ensuring old logs never pollute fresh execution traces.
- **Pure-Python Git Fallback**: Always maintain pure-Python parsing of `.git/HEAD`, `.git/refs/heads/`, and `.git/logs/HEAD` for git metadata reporting to ensure branch, commit SHA, author, and timestamp reporting function reliably even if the `git` CLI binary is absent or restricted inside runtime containers.
- **Mobile Touch Hitboxes & Auto-Zoom Prevention**: Enforce minimum $40\text{px} - 44\text{px}$ touch targets across mobile views, use safe area bottom insets (`env(safe-area-inset-bottom)`), and set `font-size: 16px !important` on form inputs on viewports $< 768\text{px}$ to prevent iOS Safari auto-zooming.
- **Two-Row Responsive Mobile Admin Header**: Flex the Django Admin `#header` into two distinct stacked rows on mobile screens ($\le 767\text{px}$)—Row 1 for `#branding` (Site Title and TOTP/Login badges) and Row 2 for `#user-tools` (View Site, Change Password, Log Out) with full width and top border separation—and assign `.admin-toolbar-row` adequate vertical margins (`margin-top: 12px !important; margin-bottom: 16px !important;`) to ensure quick-filter search inputs never collide with or obscure user utility links.
- **Automated Post-Deployment Docker System Prune**: Automatically execute volume-safe `docker system prune -a -f` and `docker builder prune -f` at the completion of deployment workflows once new containers are running and healthy. This removes superseded container images and build caches left behind by Git pulls, eliminating server disk exhaustion while strictly preserving persistent named volumes (e.g. database and SSL data).
- **Explicit Dual-Route Registration for ModelAdmin Sub-Views (`<path:object_id>/action/`)**: When creating custom views on a `ModelAdmin` that can be linked from an instance change form (`/<object_id>/change/`), register both the root pattern (`action/`) and instance-scoped pattern (`<path:object_id>/action/`) in `get_urls()` strictly before `super().get_urls()`. In client scripts, always resolve the canonical base admin URL dynamically from `window.location.pathname` (e.g. `/^(.*\/kalai\/broker\/)/`) to avoid relative path nesting issues.
- **Live Remote Git Metadata Synchronization (`get_git_metadata`)**: When querying git metadata in Deployment Hub or admin diagnostic views (`get_git_metadata()`), perform a bounded non-blocking `git fetch --quiet origin <branch>` (with timeout $\le 6$s) prior to comparing commit graphs via `git rev-list --left-right --count origin/<branch>...HEAD`. This ensures the UI reflects commits newly pushed to GitHub in real time, avoiding stale "Up-to-date" indicators. Always wrap the fetch in timeout handling and fall back gracefully if network connectivity is intermittent.

### 🚫 DO NOT
- **DO NOT Blindly Parse Fetch Responses as JSON**: Never invoke `await res.json()` without verifying JSON headers or wrapping in try/catch. When a server returns an HTML error (e.g. 403 Forbidden, 502 Bad Gateway), `JSON.parse` crashes with `unexpected character at line 1 column 1`.
- **DO NOT Append Deployment Logs Indefinitely Across Distinct Jobs**: Never use append-only mode (`"a"` / `tee -a`) across separate deployment lifecycles without clearing. Stale logs confuse operators and mask current build status.
- **DO NOT Run Migrations Immediately After Container Start**: Never invoke `manage.py migrate` directly after `docker compose restart` without verifying database socket readiness with `pg_isready`.
- **DO NOT Hardcode Desktop-Only Grid Dimensions**: Never use rigid fixed minimums like `minmax(420px, 1fr)` on admin dashboard grids; use responsive bounds such as `minmax(min(100%, 360px), 1fr)` to prevent mobile horizontal blowout.
- **DO NOT Use Fragile Relative Paths (`../action/`) in ModelAdmin Form Scripts**: Never use relative paths like `../credential-guide/` in client-side scripts running on admin change forms (`/<object_id>/change/`). Relative step-ups resolve to `/<object_id>/action/`, causing Django's standard changeform view to misinterpret the action as a primary key and crash with *"Account with ID '<id>/action' doesn't exist"*.
- **DO NOT Allow Admin Quick Filters to Overlap User Utility Tools on Mobile**: Never allow absolute positioning, zero-clearance margins, or unconstrained floats on `#user-tools` and `.admin-search-box` on screens $\le 767\text{px}$ that obscure vital user navigation links like 'View Site', 'Change Password', or 'Log Out'.
- **DO NOT Accumulate Superseded Docker Images Across Deployments**: Never omit automated system pruning during routine deployment workflows. Without post-deploy system pruning, rebuilding or updating containers after Git pulls generates dangling images and layer caches that rapidly exhaust cloud host disk space.
- **DO NOT Rely on Local `origin/<branch>` Tracking Refs Without On-Demand Fetching**: Never check git commit divergence using `git rev-list` against local tracking branches without first fetching from the remote. Tracking branches only update when an explicit network fetch/pull occurs, causing operators to see misleading "Up-to-date" status after pushing changes to GitHub.
